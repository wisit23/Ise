# Auth Service — สิ่งที่ตรวจและตกลง

ต้นทาง: thread `191c4986-dbe8-41ca-93bf-a26fa649b30a`; Mxx อ้าง [บทสนทนาเต็ม](../sources/191c4986-dbe8-41ca-93bf-a26fa649b30a-transcript.md) ดู [กติกาและสถานะรวม](../README.md)

## สิ่งที่ตรวจพบในบทสนทนา

- M03–M04: ขาดตาราง `auto_messages` ทั้ง schema และ migration เมื่อเทียบ ER ข้อ 1
- M04, M11: ใช้ schema ใน backend เป็นหลัก ไม่ใช้สำเนา `database/*.prisma` ตัดสินสถานะ
- M04 รายงาน `prisma validate` ผ่านทั้ง 4 service ซึ่งรวม Auth แต่ยังไม่ได้พิสูจน์การสมัครสมาชิกและ flow จริงกับ PostgreSQL
- รายละเอียดรายตาราง/คอลัมน์อยู่ใน [รายงาน audit เดิม](../sources/er-audit-report-original.md) รายงานนี้มาก่อนข้อตกลงภายหลัง

## ข้อตกลงที่ใช้กับ Auth

- M07: ให้ตรง ER ทุกตาราง/คอลัมน์ รายงานความต่างก่อนเปลี่ยน
- M14, M16: แก้สะกดผิด ใช้ SQL `snake_case` และชื่อมาตรฐานที่ตกลง ไม่อนุมานว่าชื่อคล้ายกันหมายถึงข้อมูลเดียวกัน
- ไม่พบการเลือกวิธีทดแทน backend เฉพาะ Auth เพิ่มเติมในข้อความที่อ่าน

## สิ่งที่ยังไม่ได้ทำ / งานค้าง

- ยังไม่ได้สร้าง `auto_messages`, ปรับ ER/schema, เขียนหรือรัน migration หรือแก้ callers ใน thread นี้
- ต้องแจกแจงโครงสร้าง/constraints/callers ตามรายงานและ ER ที่อนุมัติก่อนลงมือ ห้ามเดา type/nullability/default ที่ ER ไม่ได้ระบุ
- ต้องทดสอบ migration และ flow สมัครสมาชิกกับ DB ชั่วคราวก่อนรับรองว่าใช้ได้จริง

ผลตรวจข้างต้นเป็นรายงานในบทสนทนาเดิม ไม่ใช่การรันทดสอบใหม่ในรอบบันทึกนี้
