# Chat Service — ข้อตกลงร่วมกับ Support

ต้นทาง: thread `191c4986-dbe8-41ca-93bf-a26fa649b30a`; Mxx อ้าง [บทสนทนาเต็ม](../sources/191c4986-dbe8-41ca-93bf-a26fa649b30a-transcript.md) ดู [กติกาและสถานะรวม](../README.md)

Chat ไม่ใช่หนึ่งใน 4 service ที่ตรวจ ER ข้อ 1 รอบแรก เพิ่มบันทึกนี้เพราะมีข้อตกลงเกี่ยวกับหน้าที่ Chat ไม่ได้หมายความว่า Chat ผ่านการตรวจ ER/validate ในผล 4 service นั้น

## แนวทางที่อนุมัติ — M29/M31 ข้อ 5, M32

- Chat เป็นเจ้าของข้อความจริงแห่งเดียวสำหรับ ticket ของ Support
- Support เก็บ `ticket_chat_links` แล้วอ่าน/ส่งข้อความผ่าน Chat แทนการเก็บซ้ำใน `ticket_messages`
- หมายเหตุภายในใช้ `visibility = INTERNAL` ที่ผู้ช่วยรายงานว่ามีอยู่ใน Chat schema
- ใช้ idempotency key เดิมในการส่งซ้ำ เพื่อไม่สร้างข้อความซ้ำ
- ย้ายประวัติข้อความเดิมให้ครบก่อนเลิกใช้ storage ฝั่ง Support

## ข้อกำหนดร่วม

- ตรวจสิทธิ์ conversation และข้อความภายใน ผู้ร้องเรียน/ผู้ขายที่ไม่มีสิทธิ์ต้องไม่เห็น INTERNAL ผ่าน API หรือ notification
- แยกบทบาทคนได้รับมอบหมาย ticket กับผู้รับหน้าที่ตอบแชตตามเหตุการณ์ ไม่ถือว่าเป็นคนเดียวกันเสมอ
- Chat ติดต่อไม่ได้ต้องให้สถานะผิดพลาด/ยังไม่พร้อมอย่างตรงไปตรงมา ไม่ทำเหมือนประวัติหาย

## งานที่ยังไม่ได้ทำ

ไม่พบการแก้ schema/API/migration หรือการย้ายข้อความใน thread ต้นทาง รายละเอียด cross-service API, event/metadata, key และขั้นตอนย้ายข้อมูลยังต้องจัดให้ชัดก่อน implement ทดสอบข้อความไม่ซ้ำ การรักษาประวัติ สิทธิ์ INTERNAL และ Chat unavailable บนสภาพแวดล้อมทดสอบ ผลเหล่านี้ยังไม่ได้พิสูจน์ในรอบบันทึกนี้
